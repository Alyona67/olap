## 1. Бизнес-цель витрины
Разработать аналитическую витрину для розничной сети продуктовых магазинов, которая объединит данные о продажах, товарах, магазинах, клиентах, сотрудниках и акциях в единую модель «звезда». Витрина должна позволять руководству быстро получать ответы на ключевые вопросы: какие магазины и регионы приносят наибольшую выручку, какие категории товаров и бренды продаются лучше, как акции влияют на продажи, какие клиентские сегменты обеспечивают основной оборот, а также как меняется выручка по месяцам и сезонам.


## 2. Grain
fact_sales
Одна строка факта = одна позиция в чеке, отнесённая к конкретной продаже, дате, магазину, клиенту, сотруднику и акции.

fact_returns
Одна строка факта = один возврат по конкретной продаже, с указанием причины возврата.

fact_inventory
Одна строка факта = остаток конкретного товара в конкретном магазине на конкретную дату.


## 3. Fact-таблица
| Имя | Grain | Примечание |
|-----|-------|------------|
| fact_sales | Одна позиция в чеке | Источник — `fact_sales.csv`. Одна строка = один товар, проданный в конкретном магазине конкретному клиенту в определённую дату, возможно — в рамках акции. Связана с измерениями по date_id, store_id, product_id, customer_id, employee_id, promotion_id. |
| fact_returns | Один возврат по конкретной продаже| Источник — `fact_returns.csv`. Ссылается на sale_id из fact_sales, что позволяет связать возврат с исходной продажей. |
| fact_inventory | Остаток на дату | Источник — `fact_inventory.csv`. Показывает, сколько единиц товара product_id лежит в магазине store_id на дату date_id. |


## 4. Меры
| Мера | Тип | Определение |
|------|-----|-------------|
| Выручка | sum ok | `SUM(amount)` по `fact_sales`. |
| Количество проданных единиц | sum ok | `SUM(qty)` по `fact_sales`. |
| Число продаж | sum ok | `COUNT(*)` по `fact_sales`. |
| Сумма возвратов | sum ok | `SUM(amount)` по `fact_returns`. |
| Доля возвратов | нет | `SUM(amount) возвратов / SUM(amount) продаж`. |
| Остаток на складе | нет | `qty_on_hand`. Считаем среднее или последнее значение. |


## 5. Измерения
| Dim | Ключ | Важные атрибуты | SCD1 / SCD2 / нет |
|-----|------|-----------------|-------------------|
| dim_product | product_id | product_name, category, brand | SCD1 |
| dim_store | store_id | store_name, city, region | SCD1 |
| dim_date | date_id | full_date, year, month, month_name, day_of_week | нет |
| dim_customer | customer_id | customer_name, city, segment, gender | SCD2 |
| dim_employee | employee_id | employee_name, position, store_id | SCD1 |
| dim_promotion | promotion_id | promotion_name, promo_type, discount_pct | нет |

SCD1 — заменеям старое значение 
SCD2 — храним историю версий 
нет — справочник статичный, изменения не предусмотрены


## 6. Три бизнес-вопроса
1. Как меняется выручка по месяцам? Есть ли сезонные пики?
2. Какие категории товаров и бренды дают наибольшую выручку? 
3. Продаются ли товары со скидкой чаще, чем без неё?


## 7. Эталонный SQL одной метрики (общая выручка)
SELECT SUM(amount) AS total_revenue
FROM read_csv_auto('data/raw/fact_sales.csv');


## 8. Риски / cut
Основные ограничения проекта связаны с синтетической природой данных - они сгенерированы программно для учебных целей и не отражают реальный бизнес. Названия товаров, магазинов, клиентов и сотрудников - условные. Для анализа продаж, возвратов и остатков используются синтетически сформированные таблицы, а отчёты демонстрируют методику анализа, а не реальную ситуацию на рынке. Потоковая загрузка данных в проекте не предусматривается. Подробное обоснование исключённых возможностей приведено в cut.md.
